# Redia — 新アプリ開発プロジェクト

このフォルダだけを新しい場所へコピーし、プロジェクトフォルダとして開けば開発できる引き継ぎパッケージです。旧アプリ・親フォルダ・過去の会話・作成者のローカル環境は不要です。

フォルダ名 `Migration` は引き渡し時の名前です。変更して構いません。**開いたフォルダ自体を新アプリのルート**として使い、その直下へ `package.json`・`src/` 等を作成します。`desktop-next/` や `Migration/Migration/` は作りません。

## 開発を始める

1. 必要なら、このフォルダを新しい開発先へコピーします。
2. コピー先のフォルダ自体をCodexのプロジェクトとして開きます。
3. [着手指示](START_DEVELOPMENT.md) の「最初に渡すプロンプト」を送ります。

エージェントは [AGENTS.md](AGENTS.md)、[確定仕様](docs/next-app-spec.md)、[開発手順](docs/next-app-development-plan.md)、[現在地](docs/PROGRESS.md) を読み、Phase 0から実装します。まず仕様を再提案する必要はありません。


```powershell
node scripts/check-prototype.cjs
```

## 開発・起動・ビルド

Windows x64、Node.js 24.22.1以上の24系、pnpm 11.25.0を使用します。NodeとpnpmをPATHに設定してください。npmは開発手順の前提にしません。pnpmの導入方法は [公式手順](https://pnpm.io/installation) を参照してください。

プロジェクトルートで実行:

```powershell
pnpm install --frozen-lockfile
pnpm dev
```

`pnpm dev` はmain/preloadをビルドし、ループバック限定のViteサーバーとElectronを起動します。rendererはHMR対応。main/preloadを変更した場合はウィンドウを閉じて再実行してください。通常の終了はウィンドウを閉じます。保存完了を待ち、失敗時は案内します。端末のCtrl+Cやプロセス停止は強制終了となり得るため、mainへ退避できた下書きまでが復旧対象です。

```powershell
pnpm typecheck
pnpm test
pnpm build
pnpm start
```

`pnpm start` はビルド済みの画面をオフラインで起動します。先に `pnpm build` を実行してください。初回のElectron起動では実行ファイルの追加ダウンロードが発生するため、ネットワークが必要です。

```powershell
pnpm test:smoke
pnpm test:smoke:dev
pnpm package:dir
pnpm test:smoke:packaged
pnpm test:phase1
pnpm test:phase2
pnpm test:phase3
pnpm test:phase4
pnpm test:phase5
pnpm test:phase6
pnpm test:phase7
```

起動テストは各2回、実際のElectronで起動→React描画／API接続／Node権限分離／SQLite接続確認→終了を行います。テストごとの保存先と画面証跡 `shell.png` は `test-artifacts/smoke-*/` 内です。既存の開発用・製品用データを使いません。開発版テストはポート5173が空いている状態で実行してください。配布版テストは先に `pnpm package:dir` を実行します。

`pnpm test:phase1` は別ビルドの操作テストを使い、作成・一覧／詳細編集・全6状態・日付・保存障害・通常終了直前の保存・再起動・異常終了・復旧・手動バックアップを実Electronで検証します。異常終了の段階では意図的に終了コード17で停止し、その次の起動で復旧します。全体の成功は `PHASE1_ALL_PASSED` と終了コード0で確認します。証跡は `test-artifacts/phase1-*/`。入力値と固定日付はテストだけにあり、製品へは収容しません。テスト時のみソフトウェア描画を使います。Windows IME実入力の代わりに、合成したcomposition中のEnter拒否を検査している点に注意してください。

`pnpm test:phase2` は一時データを作成し、3回の実Electron起動で検索・複数条件・いつかの独立性・任意列・直前に開いた対象／縦横位置の復元・再起動後保持・完了からの再開・ページとテーマの独立したアーカイブ／復元を検証します。全体の成功は `PHASE2_ALL_PASSED` と終了コード0。明暗テーマの画面証跡は `test-artifacts/phase2-*/` です。

`pnpm test:phase3` は一括登録・部分失敗の修正／再試行、実ファイル2件のドロップ、重複再利用、文脈別用途メモ・並べ替え、共通情報反映、検索・絞り込み・条件と位置の復元、参照切れ修正、登録解除・原本不変・再起動を検証します。8プロセスで資料ごとの保存障害分離・終了時の未登録入力保護・空の追加画面からの終了、資料の自動保存失敗／再試行・異常終了からの復旧・終了直前保存、20件の関連先がある詳細の表示密度とスクロール・末尾編集、関連ページ追加画面の検索・絞り込み・新規作成・失敗時保持と再試行、資料タイトルからの原本起動と行余白からの詳細表示も確認します。テスト専用のテキストを既定アプリで開き、存在しない共有先へのアクセス失敗とローカル操作の継続も確認します。原本の起動先アプリは必要に応じて閉じてください。全体の成功は `PHASE3_ALL_PASSED` と終了コード0。証跡は `test-artifacts/phase3-*/` です。

資料は所在だけを登録し、原本を取り込みません。追加モーダルでファイル／フォルダー選択、1行1件のパス／URL貼り付け、ページや目録への複数ドロップを利用できます。同じ参照先は既存資料を再利用します。ページ内の追加画面は新規登録と登録済みリストを同時に表示します。資料名・参照先・説明・用途メモの検索、種類・テーマ・未関連の絞り込み、並べ替えで探し、行の「追加」で関連付けます。資料タイトルで原本を開き、種類欄など行の余白で詳細を開きます。ページ内では左のハンドルをドラッグして並べ替えます。行の「•••」から関連解除・登録解除も操作できます。テーマには直接関連した資料と配下ページの資料を重複なく表示します。詳細上部でタイトルとリンク、下部で関連先ごとの用途メモを編集できます。詳細内の「原本を開く」も利用でき、説明・種類は折りたたみ欄から編集できます。

資料の共通情報・用途メモは自動保存します。用途メモはページ内の一覧や、資料詳細内の各関連先の隣で直接編集できます。テーマ内や資料目録の一覧ではメモを表示せず、関連テーマ・ページ名を左詰めで横並びにします。横スクロールは設けず、隠れる関連先があれば「…」を表示し、詳細で全件を確認できます。ページ／テーマ内では資料名の下のパスを表示せず、名前のホバーで参照先を確認します。通常の詳細操作は「閉じる」です。閉じる・関連ページへの移動時はその資料だけを保存し、失敗しても入力を保持して移動できます。保存失敗時に表示する「再試行」は保存をやり直し、詳細を開いたままにします。別資料の保存エラーは無関係な操作を妨げません。入力はアプリ専用の復旧下書きへ退避し、異常終了後はHOMEの案内から資料目録で復旧・明示的な破棄ができます。正常終了では全資料・ページと表示設定の保存を待ちます。空の資料追加画面は終了を妨げず、未登録の参照先が残る場合は画面へ戻るか破棄して終了するかを確認します。保存失敗や表示設定エラーは上部の警告アイコンと文言で通知します。種類を推定できないオフライン参照はファイルとして登録し、共通情報からフォルダーへ修正できます。

手動確認用の一時データ環境は `pnpm test:manual` で起動できます。毎回 `test-artifacts/manual-*/` を新規作成し、通常の開発／製品データを使いません。日本語IMEでテーマ・通常ページ・関連ページの新規作成の変換確定Enterが誤登録にならないことと、本文での改行を確認してください。このテスト用ビルドに限りCtrl+Shift+F9でDB書き込み障害を切り替えられます。障害中に入力を編集してウィンドウを閉じると、保存失敗時の案内を確認できます。再度Ctrl+Shift+F9で障害を解除し、保存を再試行してください。通常の製品ビルドにはこの障害切り替えを含みません。

`pnpm package:dir` の成果物は `release/win-unpacked/Redia.exe` です。配布時はexe単体ではなく `win-unpacked` フォルダ全体が必要です。NSIS生成コマンドは `pnpm dist:win`。0.1.4の修正版は `release/redia-0.1.4/` にフォルダー版と `Redia Setup 0.1.4.exe` を生成済みです。インストール・署名・更新は未確認。現在は未署名で、公開や自動更新は行いません。

アイコンは `assets/app-icon.png` と `assets/app-icon.ico`。ウィンドウ・配布exe・インストーラー・左上ロゴで共通使用します。原稿は `design/icon-concepts/redia-v1/C-ribbon-r.png`。再生成はPython 3とPillow（生成時8.3.1）で `python scripts/generate-icons.py` を実行します。通常の起動・ビルドにPythonは不要です。名称はRediaへ変更し、appId・データ保存先は維持します。

## 構成と保存先

| 場所 | 責務 |
| --- | --- |
| `src/main/` | ウィンドウ、安全なIPC、SQLiteとMigration、下書きジャーナル、手動バックアップ、専用保存先、ログ |
| `src/preload/` | `window.workspace` の用途別メソッドのみを公開。汎用IPC・Node・パス操作を渡さない |
| `src/shared/` | APIの型と境界検証 |
| `src/renderer/` | Reactの表示。試作データや擬似保存なし |
| `tests/` / `scripts/` | 境界テスト、開発・ビルド・実Electronの起動テスト |
| `dist/` / `dist-electron/` / `release/` | 自動生成物。編集・リポジトリへの追加は不要 |

通常のデータ配置は `%LOCALAPPDATA%/EngineeringWorkspace/development/`（開発）と `%LOCALAPPDATA%/EngineeringWorkspace/production/`（配布版）。ソースやexeの配置場所・フォルダ名から独立しています。各環境の中に `database/workspace.sqlite`、`attachments/`、`drafts/`、`logs/`、`session/`、`backups/` を分離します。初回起動でDBとスキーマを作成し、以降はMigrationで管理します。旧アプリの保存先は使用しません。

起動失敗時は各環境の `logs/app.log` を確認してください。テストは `--smoke-test` と絶対パスの `EW_TEST_DATA_DIR` の両方を必須にして、通常データへのフォールバックを禁止しています。外部資料は参照と既定アプリでの起動のみ行い、原本を変更しません。実データ運用はバックアップ・復元を含む受入確認後です。

## Phase 1で使える操作

- ホームの「新規ページ」はタイトルだけで未着手のページを作成します。テーマ欄の「＋」でテーマを作成し、テーマ内で作ったページはそのテーマへ所属します。
- 作成が成功したら新規作成ウィンドウを閉じ、元の一覧・ページへ戻ります。詳細には自動遷移しません。ホームの見出しは「HOME」とし、装飾的な補足文章は表示しません。
- 一覧から状態・サマリを直接編集できます。タイトルで詳細を開き、タイトル・状態・テーマ・サマリ・本文を編集します。期限と確認日は任意で、設定操作から展開できます。
- 詳細はプロパティ→本文→関連資料→関連ページの順で表示し、本文の見出しを置きません。関連ページの「ページを追加」は、上部でタイトルだけの新規作成、下部で登録済みページの検索・状態／テーマ絞り込みと関連付けを行うウィンドウです。新規は未着手で元ページのテーマと関連を継承し、成功後は閉じて元ページに残ります。「気づきを残す」の専用ボタンは非表示です。関連リンクは双方向にたどり、ページを残して関連だけ解除できます。
- 編集は自動保存です。保存中／保存済み／失敗を上部へ表示します。失敗時も入力を残し、再試行できます。作成途中でモーダルを閉じた入力はホームの「作成途中の下書き」から再開できます。
- 異常終了後に未保存の下書きがある場合、起動時に復旧候補を表示します。復旧するか、確認後に破棄できます。
- 設定の「バックアップを作成」で専用backups領域へDB・管理添付・復旧下書きと検証用manifestを保存します。復元画面と自動実行はまだ実装していません。

## Phase 2で追加した操作

- HOME主一覧は未着手・進行中・待ちだけを表示します。検索はタイトル・サマリ・本文が対象で、状態・テーマ（未所属を含む）の条件とANDで絞り込みます。検索語は空白区切りの全語を照合し、全角／半角と英字の大小をそろえて検索します。入力や条件は見える形で解除できます。
- タイトル・状態・更新日時・期限・確認日で並べ替えられます。日付未設定はどちらの方向でも末尾です。「表示列」から期限・確認日・更新日時を追加できます。横スクロール中もタイトル列を固定します。
- 一覧と「いつか」は独立してスクロールし、主一覧の検索・フィルターは「いつか」へ影響しません。期限超過・当日期限・確認日到来を小さく表示し、「いつか」の日付確認件数から対象へ移動できます。日付が来ても状態や日付を自動変更しません。
- テーマ一覧の「完了・中止を含む」で終了済みを表示できます。完了・中止のページは横断検索からも参照できます。アーカイブは明示的に含められます。
- 検索条件・並び順・任意列・直前に開いた対象・縦横スクロール位置は、HOME／テーマごと／検索ごとに保持し、再起動後も戻します。詳細からの「戻る」で元の一覧を再表示します。表示設定の保存が失敗した場合も現在の条件を保持し、再試行できます。
- 行のアーカイブアイコン、詳細やテーマ上部のアーカイブ操作で非表示にできます。復元は「設定」→「アーカイブを管理」。アーカイブした内容は復元するまで読み取り専用です。テーマのアーカイブで子の状態や個別アーカイブ値は変えず、復元後もその値を保ちます。原本やページを物理削除しません。

Phase 1で保存したDBは初回起動時にスナップショットを作ってスキーマ版2へ更新します。業務項目を作り直したり削除したりせず、一覧設定用テーブルを追加します。

独立した計画・ガントまで実装済みです。次はPhase 6の報告画像とバックアップ・復元です。

## Phase 4で追加した操作

ページの「資料を追加」では、登録済み資料を所属テーマで絞り込んだ状態から選べます。テーマ条件を変更するか「条件を解除」で全資料を探せます。開き直すと現在の所属テーマが初期値になり、未所属ページでは「すべての関連」から表示します。

- 本文は整形した状態で編集できます。行頭の `# `／`## `〜`###### ` で見出し、`- ` で箇条書き、`1. ` で番号付きリスト、`[ ] `／`[x] ` でチェックリストへ変換します。半角スペースを入力すると変換します。書式ボタンは常設せず、本文を右クリックして標準・見出し・太字・斜体・各リスト・リンクを操作します。Shift+F10でも同じメニューを開けます。既存の文字列をMarkdownとして自動変換することはありません。
- チェック項目内を右クリックして「ページにする」を押すと、文字をタイトルへ引き継いだ関連ページ追加画面を開きます。作成後は未着手となり、テーマと関連を継承します。元の本文とチェック状態を保持します。
- 画像は本文を右クリックした「画像を追加」またはクリップボード貼り付けから取り込みます。PNG/JPEG、1件20MiB・2400万画素以内です。元ファイルを変更せず、管理用PNGを専用attachments領域へ保存します。クリックで拡大し、画像の右クリックメニュー「本文から画像を削除」で本文の参照を除けます。元画像を移動しても管理画像は表示できます。参照を消した直後の物理削除は行わず、バックアップにも含めます。
- 画像の保存に失敗したら入力を保持し、「画像を再試行」で続行できます。読み取れない画像などは「未保存の画像を破棄」で確認後に取り消せます。未保存画像が残る場合は終了やバックアップを成功扱いしません。
