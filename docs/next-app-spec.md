「確定」は機能と操作の方向性を指す。配置・列幅・余白・スクロール構成は実装時に調整する。2026-11-06のユーザー更新により、計画は単一日程へ簡略化し、当初予定・実績の比較は表示しない。

2026-11-07のユーザー指示により、初期版候補の作成後も利用しながら修正を継続する。既存データ・原本保護・入力保護を維持し、新しい指示と確認結果を文書へ反映する。未実施の実機確認は受入完了とせず、[継続改修](MAINTENANCE.md) に再確認手順を残す。

## 1. 目的と利用環境

欲しい情報や資料にすぐアクセスでき、入力がスムーズで、管理に時間を取られない個人用Windowsデスクトップアプリ。

主な用途は、資料を探すこと、今取り組むことを確認すること、将来取り組むことを忘れずに残すこと。資料は検索だけでなく、実験・検証などの文脈に集めて参照する。詳細な記録や計算はWord・Excel等に残す運用を支える。

- Electron・TypeScript・Reactで新規開発する。
- 個人利用・ローカル優先。SQLiteの稼働DBを共有ドライブ上で共同編集しない。
- ページ・資料目録はオフラインでも操作可能。外部資料の利用可否は参照先の接続状態に依存する。
- 旧アプリから移行する実データはない。本フォルダが独立した新アプリのプロジェクトルート。旧WPFアプリや親フォルダのファイルは不要で、参照・変更しない。新アプリの保存領域も専用にする。
- Notionのシンプルなページと表形式を参考にする。旧アプリの機能・項目を自動的にすべて引き継がない。

## 2. 情報構造

| 単位 | 役割 | 必須入力 |
| --- | --- | --- |
| テーマ | 開発テーマなど仕事をまとめる場所 | 名称 |
| ページ | 検討・実験・作業・気づきを残す共通のページ。画面表記も「ページ」に統一 | タイトル |
| 資料 | ファイル・フォルダー・URLの所在を登録する目録 | 参照先。表示名は自動設定可能 |
| 計画行 | 報告・日程管理用の日程と、必要なページへの関連 | 名称。日程は後から設定可能 |

### 2.1 ページの共通プロパティ

| プロパティ | 扱い |
| --- | --- |
| タイトル | 必須。空白のみは不可 |
| 状態 | 6種類から選択。作成時に自動設定 |
| テーマ | 最大1つ。未所属で作成可能 |
| サマリ | 任意の短文。実施条件・現在の状況・メモなど自由に記述 |
| 本文 | 任意。文章・見出し・箇条書き・チェックリスト・リンク・画像 |
| 期限 | 任意。取り組みを完了させたい日 |
| 確認日 | 任意。内容や着手条件を見直す日 |
| 関連資料 | 複数。用途メモ・並び順は関連付けごとに保持。初版ではグループ化しない |
| 関連するページ | 複数。別ページへの関連リンク |

作成日時・更新日時・内部ID・アーカイブ状態はシステムが管理する。表示コード、優先度、分類、タグ、仮説・検証計画・結論などの個別入力欄は初期版に設けない。

サマリは本文からの自動要約ではなく手入力。状態変更で消去・置換しない。一覧と詳細ページのどちらからも同じ値を編集する。本文との重複入力は要求しない。

### 2.2 状態とホームへの表示

| 状態 | 意味 | ホーム主一覧 | ホーム「いつか」欄 |
| --- | --- | --- | --- |
| 未着手 | 取り組む予定だが、まだ始めていない | 表示 | 非表示 |
| 進行中 | 現在取り組んでいる | 表示 | 非表示 |
| 待ち | 回答・装置・結果などを待っている | 表示 | 非表示 |
| 完了 | 取り組みを終えた | 非表示 | 非表示 |
| 中止 | 取り組みを打ち切った | 非表示 | 非表示 |
| いつか | 将来または条件がそろったら取り組む | 非表示 | 表示 |

- ホーム・テーマからの通常作成は「未着手」。テーマ画面では所属テーマを継承し、ホームでは未所属で作成できる。
- ページ内の「ページを追加」から新規作成する場合も「未着手」とし、元ページのテーマと関連を自動設定する。「気づきを残す」の専用導線は表示しない。既存ページの「いつか」状態や関連は変更しない。（2026-11-05 ユーザー更新）
- どの作成経路でも同じプロパティを持つ。状態は一覧・詳細のどちらからも6種類すべてへ変更可能。
- 特定の作成経路だけに「次の状態へ」専用ボタンを設けない。状態変更による他フィールドの自動更新を行わない。
- 完了・中止でも本文・資料・関連情報は保持する。テーマ内一覧や検索から参照し、状態を戻して再開できる。

### 2.3 関連と派生

気づきを含む作業は本文内の子要素ではなく、必要に応じて独立したページとして登録できる。元ページに関連ページとして表示し、関連先からも戻れる。複数の実験から同じページを参照できる。

初期版に親子階層や子ページを必須とする構造は設けない。テーマは所属を表し、関連リンクは文脈を表す。テーマを変更しても関連リンクと資料は保持する。異なるテーマ間の関連を理由にページを複数所属させない。

短い作業は本文のチェックリストに残せる。独立して追跡したい場合は関連ページ追加画面で新規ページを「未着手」で作り、元ページへのリンクを残す。「いつか」にしたい場合は作成後に状態を変更する。

## 3. 画面と操作

### 3.1 共通ナビゲーション

左サイドバーに検索、ホーム、テーマ、資料目録、計画を配置し、設定は下部に置く。テーマをサイドバーで選び、上部のテーマタブは設けない。起動時はホームを表示する。

上部のパンくずは、ページでは「ワークスペース ＞ 所属テーマ名 ＞ ページ名」、テーマでは「ワークスペース ＞ テーマ名」とする。未所属の項目はテーマ名の位置へ「未所属」と表示する。ワークスペースからHOME、テーマ名から該当テーマへ移動できる。項目名・所属を編集した場合も表示へ反映し、長い名称は省略表示から全文を確認できる。

詳細から戻ると、遷移元の一覧・検索条件・並べ替え・スクロール位置を復元する。直前に開いた対象は戻る位置やフォーカスの復元に使うが、行全体の選択色は付けない。再起動・画面復帰・マウスを重ねた際も、一覧の行全体はハイライトしない。ボタン・入力欄の操作反応とキーボードのフォーカス表示は維持する。ホーム等のフィルター・表示列・並べ替えは再起動後も保持する。設定したフィルターは見える形で表示し、解除できる。（2026-11-04 ユーザー指示）

### 3.2 ホーム

画面の見出しは「HOME」。標語や装飾的な補足文章は表示しない。これは他画面の作成導線にも適用し、入力名・空の状態・保存失敗や確認操作に必要な説明は残す。

主領域は全テーマ横断のページを表示する表。基本列はタイトル・状態・テーマ・サマリ。期限・確認日・更新日時は任意で表示する。テーマ未所属も含める。

- 主一覧の母集団は未着手・進行中・待ちに固定する。フィルターを解除しても完了・中止・いつかは含めない。
- タイトル・本文・サマリを検索し、状態・テーマ（未所属を含む）で絞り込む。条件同士はANDで適用する。
- タイトル・状態・更新日時・期限・確認日で昇順／降順を選択可能。未設定の日付は昇順／降順とも末尾、同値は安定した順序とする。
- 一覧内で状態とサマリを直接編集する。タイトルからページを開く。
- 項目が表示条件から外れた場合は即時再評価し、変更内容を控えめに通知する。状態を勝手に戻さない。

主一覧の外に「いつか」欄を常設し、タイトル・サマリ・関連元・必要な確認日を表示する。主一覧の検索やフィルターに左右されず、初期状態から展開する。0件でも見出しと空の状態を表示する。独立した「いつか」画面は設けない。

主一覧と「いつか」欄は同じ項目を重複表示しない。状態変更で表示先を再評価する。「いつか」の件数が増えても存在と確認日到来を見落とさない配置にする。具体的な高さ・スクロール・ページ分割は実装時に調整する。

### 3.3 テーマ

テーマ名、任意の短い説明、ページ・資料・計画への導線を持つ。テーマ名だけで作成できる。

テーマページのページ一覧では、所属テーマが自明なので「テーマ」列を表示しない。基本列はタイトル・状態・サマリとし、期限・確認日・更新日時は任意表示する。

ページ一覧は全6状態を確認でき、完了・中止を表示する切り替えを用意する。初期表示は完了・中止を除き、切り替え条件を明示する。通常作成はテーマを継承する。

「完了・中止を含む」は検索・フィルター・並べ替えと同じ行に置き、単独の段を作らない。HOME／テーマのフィルター下・ページ一覧末尾、関連資料表の後ろに装飾用の区切り線を置かない。表の列見出しや行同士を区別する線は必要最小限に保つ。（2026-11-05 ユーザー指示）

テーマの資料一覧は、テーマへ直接関連付けた資料と、配下のページから参照する資料を重複排除してまとめる。どのページからの参照かを確認できる。

### 3.4 ページ

タイトルに続き、共通プロパティ、本文、関連資料、関連ページの順に表示する。本文の見出しは表示しないが、編集欄のアクセシブルな名前は保持する。サマリは状態を問わず使える。期限・確認日などの空欄を大量に常設しない。（2026-11-05 ユーザー指示）

関連資料は本文の直後に置く。初版ではグループ化せず、1つの一覧で並べ替えられる。資料の役割や使い方は、任意の用途メモで記録する。グループの見出しや編集欄は設けない。（2026-11-04／05 ユーザー指示）

ページ／テーマ内の関連資料は、資料名の下にパスを重ねて表示しない。参照先は資料名のホバーで確認できる。テーマ内・資料目録など複数の関連先を表示する一覧では用途メモを表示せず、関連テーマ・ページ名だけを左詰めで横に並べる。横スクロールは設けず、収まらない場合は「…」で隠れた関連先があると示す。ページではそのページ固有の用途メモのインライン編集を維持する。（2026-11-05 ユーザー指示）

資料のタイトルをクリックすると原本を開く。種類欄など行の余白をクリックすると詳細ウィンドウを開く。入力欄・関連先リンク・ドラッグ・行メニューの操作で詳細を誤って開かない。詳細上部でタイトル・リンクを編集し、下部に全関連テーマとページを縦の一覧で表示し、各関連先の隣で用途メモを確認・編集できる。ページ名からそのページへ移動できる。詳細内の「原本を開く」も利用できる。編集は自動保存・失敗時保持・復旧下書きを維持する。説明・種類は折りたたんで編集できる。（2026-11-05 ユーザー更新）

資料詳細は、文字サイズを保ちながら上下の余白・行高を抑え、関連先を多く見渡せる配置にする。関連先が多い場合はリスト内を縦スクロールし、上部のタイトル・リンクと下部の失敗時の案内・閉じる操作を画面内に保つ。通常の保存状態は表示しない。メモ入力時には欄を広げて編集できる。（2026-11-05／07 ユーザー更新）

ページ内の資料順序はドラッグハンドルをマウスで移動して変更する。右の行メニューに上下移動は設けない。保存失敗時は元の順序を保持し、並べ替えで用途メモや関連先を変更しない。テーマの直接関連資料も同じ操作に対応し、配下ページから集約した資料の順序は元ページで変更する。（2026-11-05 ユーザー指示に基づく実装）

資料の追加画面では、新規登録の操作と登録済み資料の一覧を同時に表示し、タブで切り替えない。登録済み資料はプルダウンではなく、資料名・参照先・種類・関連テーマを示すスクロール可能な一覧から指定する。資料目録と同じ検索、種類・関連テーマ・未関連の絞り込み、名前・更新日時の並べ替えを利用できる。未追加の行は「追加」、この関連先へ追加済みの行は「解除」とし、成功後も画面を開いたまま続けて操作できる。解除はこのページ／テーマへの直接の関連だけを外し、資料の登録・原本・ほかの関連先と用途メモは維持する。未保存の用途メモを先に保存し、失敗した場合は解除せず入力を保護する。新規登録が成功した場合は従来どおり画面を閉じ、元ページに残る。テーマの資料追加にも同じ操作を適用する。（2026-11-07 ユーザー更新）

ページから関連資料を追加する際、登録済み資料の一覧はそのページの所属テーマで初期絞り込みする。未所属ページでは「すべての関連」を初期表示する。テーマ条件は手動変更・解除でき、追加画面を開き直すたびに現在の所属テーマを初期値にする。該当資料が0件でも自動解除しない。（2026-11-06 ユーザー指示）

関連ページの「ページを追加」は、上部に新規ページのタイトル欄と「作成して追加」、下部に登録済みページの検索・状態／テーマフィルター付きリストを同時表示する。検索は既存一覧と同じタイトル・サマリ・本文の空白区切り全語照合。元ページ自身とアーカイブ済みを候補から除き、追加済みは表示して操作を無効にする。新規作成はタイトルだけで未着手となり、テーマと元ページへの関連を継承する。ページ作成と関連付けは一体で保存し、失敗時に孤立した新規ページを残さない。既存／新規の追加成功後はウィンドウを閉じて元ページに残り、失敗時は入力・検索条件を保持する。作成途中のタイトルは既存の復旧下書きへ退避する。「気づきを残す」ボタンは一旦非表示とする。（2026-11-05 ユーザー指示）

### 3.5 資料目録

資料追加のパス／URL欄へ貼り付ける際、クリップボードのHTMLリンクに表示名が含まれていれば、新規資料の名前として取り込み、リンク先を参照先へ登録する。SharePoint／OneDrive上のOfficeファイルの名前付きリンクやWebページのリンクを同じ方式で扱う。取得した名前は登録前のタイトル入力欄で確認・修正できる。通常のURL／パスも推定名を入力欄へ表示し、複数件はそれぞれ編集できる。タイトルだけを追加の必須入力にはせず、空欄は従来の推定名で登録する。既存の参照先は登録済みと表示して既存名を読み取り専用で確認し、同じURLの貼り付けで共通名を上書きしない。登録時にもmainで重複を確認し、再利用した場合はメッセージで知らせる。取得のためのWebアクセス・Microsoft 365へのログインは行わず、貼り付け時のデータだけを読む。（2026-11-07 ユーザー更新）

未関連の資料を含む全登録資料を横断リストで表示する。基本列は資料名・種類・参照先・関連テーマ・関連するページ。説明と用途メモも参照できる。

資料の種類は参照先の拡張子から自動判定し、PowerPoint・PDF・Word・Excel・画像・テキスト等を示す。URLはパスやファイル名を含むパラメーターを確認し、拡張子が見えない共有リンクは資料名の拡張子を補助に使う。判断できないものは汎用ファイル／URL、フォルダーはフォルダーとして扱う。資料名の左に色と形・文字で識別できる共通アイコンを置き、資料目録・テーマ・ページ・追加画面・横断検索に適用する。種類での絞り込みにも対応する。外部原本やリンクを書き換えず、判定用の分類プロパティは追加しない。（2026-11-07 ユーザー指示）

- 資料名・参照先・説明・用途メモで検索し、種類・関連テーマ・未関連で絞り込む。名前・更新日時で並べ替えられる。
- ファイル／フォルダーの選択、複数ファイルのドロップ、パス／URL貼り付けで登録する。名称と種類を推定し、追加の必須入力を要求しない。
- 複数登録は一括で行い、1件ずつ確認ダイアログを出さない。失敗した項目を明示し、部分的に再試行できる。
- 同一参照先は既存の資料を再利用して関連付ける。ファイルパスとURLの正規化ルールは区別し、URLを一律小文字化しない。
- 資料タイトルから原本を既定アプリ／ブラウザーで開き、行の余白から資料詳細を開く。詳細では共通情報の編集・全関連先の用途メモ確認／編集を行う。行メニューは詳細表示・関連解除・登録解除を担当する。
- 表示名・参照先・説明は資料共通。用途メモ・並び順は関連先ごとに保持する。
- 共通情報を編集すると、同じ資料を参照するページへ反映する。用途メモの変更はその関連先だけに反映する。
- 原本が移動・削除・未接続等で開けない場合、参照先と失敗内容を示し、参照先を指定し直せるようにする。自動的な空ファイル作成はしない。
- 関連項目名からそのページへ移動できる。戻った際は資料目録の表示条件を復元する。
- 資料の登録・名称変更・登録解除によって、原本をコピー・移動・改名・削除しない。登録解除は関連数を示して確認し、目録と関連付けを削除する。

例: 「温度特性の実験」から装置マニュアル、手順書、実験メモ、結果計算シートを開く。同じマニュアルを別の実験にも関連付け、それぞれ異なる用途メモを持てる。

### 3.6 横断検索

Ctrl+Kまたはサイドバーで開き、テーマ・ページ・資料を検索する。空欄時は最近開いた対象を表示する。

検索対象はアプリ内の名称・サマリ・本文のテキスト・説明・用途メモ・パス／URL。Word・Excel・PDF等の原本本文と画像内の文字は検索しない。完了・中止は検索対象、アーカイブ済みは初期状態で除外し、明示的に含められる。

上下キーで選択、Enterで開く、Escで閉じる。資料は原本を開き、テーマ・ページはアプリ内ページへ移動する。非同期検索では古い結果を破棄し、検索中・失敗・結果なしを区別する。

Ctrl+Kとサイドバーの検索は共通の検索ウィンドウを開き、入力欄へフォーカスする。画面を離れずに閉じられ、未操作の結果行を自動で選択表示しない。検索は空白区切りの全語を照合し、全角／半角・英字の大小をそろえる。空欄は最近開いた対象のうち表示条件に合う20件、検索結果は先頭50件と総件数を表示する。50件を超える場合は検索語の追加を案内する。これらは結果表示数の設計値で、登録件数の上限ではない。

### 3.7 期限・確認日

両方とも任意の時刻なし日付。独立に設定・解除でき、相互の前後関係を制限しない。

- 主一覧の対象項目では、期限超過・当日期限・確認日到来を一覧の表示／小さな案内で把握できる。
- 「いつか」は別枠内で日付到来を表示する。期限・確認日が来ても主一覧へ自動移動させない。
- 完了・中止・アーカイブ済みは日付の案内対象から除外する。
- 確認日到来後も自動的に状態・期限・確認日を変更しない。確認後に日付を解除するか次回へ変更する。
- 日付なしでも運用可能。OS通知は初期版の対象外。

## 4. 計画・ガント・報告画像

### 4.1 日程とページの分離

テーマごとの計画と全テーマ横断表示を用意する。計画行へ複数のページを関連付けられる。関連なしでも計画でき、同じページを複数行から参照できる。

ページに開始日・終了日を要求しない。計画行の編集・削除によってページの本文・状態・期限・確認日を変更しない。ページから「計画に追加」で新規行を作るか既存行に関連付ける。

画面は1行につき1つの日程・1つのバーとする。最新予定と実績を別々に入力する運用はやめ、既存の開始／終了日を「日程」として編集する。当初予定と実績の旧データは削除・上書きせず保持し、当初計画の保存・比較・実績入力のUIは表示しない。（2026-11-06 ユーザー更新）

日程未定の行も、指定済みと同じ順序の一覧に置き、カレンダーにはバーを出さない。片側日付と単日の場合も1日分のバーで表示する。タイトルはバーに重ねて左詰めにし、日程のバー幅より長い場合は右へはみ出して省略せず表示する。行高36px・文字14pxは維持し、縦方向にはバー内に収める（2026-11-07 ユーザー訂正）。月は日番号の上へまとめ、日付列には日だけを表示する。土日は背景・文字色で区別する。「今日」は以前の横スクロール位置に関係なく、今日が画面内に見える位置へ移動する。

タイトル列は「«／»」で折りたたみ・再表示でき、折りたたむとカレンダーを広く使える。カレンダーには独立した縦の高さ上限を設けず、行数に応じて伸ばし、画面全体で縦スクロールする。日ビューは廃止する。Full HD・100%・全画面を基準に、週は約14日、月は約1.3か月（36～40日程度）、クオーターは約3か月が見える固定の日幅とする。小さいウィンドウに合わせて全期間を縮めず、時間軸を横スクロールできる。横ホイール・Shift＋縦ホイール・横スクロールバーで左右へ移動し、通常の縦ホイールは全体の縦移動に使う。クオーターの日付ラベルは月曜日だけ、週／月も日番号が重なるほど狭い場合は月曜日だけとする。月はその上にまとめる。今日への移動と行の並べ替えを維持する。（2026-11-07 ユーザー補足を反映）

### 4.2 カレンダーの直接操作と詳細パネル

- 日程未定行のカレンダーで日をクリックすると、その日を開始・終了日とする。ドラッグでは両端を含む期間を設定する。
- 指定済みのバーは1日単位で移動し、両端で伸縮する。ドラッグ中はプレビュー、解放で保存、Esc／中断で取消。Undo／Redoを維持する。
- クオーターでは誤操作防止のためマウスでの日程設定・バー移動・伸縮・空欄カレンダーからの日付付き作成を無効にする。バーのクリックで詳細を開き、日付入力から修正できる。行の追加／挿入や並べ替え、キーボード操作は維持する。日程のマウス操作は週／月で利用する。（2026-11-07 ユーザー更新）
- 行の末尾の「+ New」で日程未定行を追加し、その場でタイトルを入力する。タイトル列の開閉にかかわらず、最下部の空欄カレンダーをクリック／ドラッグして日程付きの新規行を作れる。
- タイトル列が開いているときは各行左の「+」で、その行の直下へ新しい行を挿入できる。タイトルはインラインで入力し、Enterまたはフォーカス移動で確定する。IME確定Enterは登録しない。新規入力中のEscで追加を取り消せる。
- 行名またはバーをクリックすると、画面右から縦長の詳細パネルを表示する。下部の編集枠は置かない。パネルを開いていてもカレンダーを操作でき、閉じる／Escまたはパネル外の余白クリックで戻せる。タイトル列を閉じたときは「+ New」の表示も隠し、空欄カレンダーの追加操作を維持する。
- 詳細のプロパティはタイトル、テーマ、開始日、終了日、関連付けられたページとページを関連付けるボタン。ページ名からページへ移動できる。削除と関連解除は既存の行操作として維持する。
- 開始・終了の順序と存在する日付を検証し、保存失敗でも入力・下書きを保持する。計画の編集は関連ページの状態・本文・期限・確認日を変更しない。

計画の検索・テーマ・表示密度／開始日・タイトル列の開閉・選択行・カレンダーの位置は保持する。既存の最新予定を単一日程へ使い、過去の当初予定・実績は非表示で保存し続ける。画像は操作と見た目の参考で、Notionの機能全体やサンプルデータを製品へ流用しない。

### 4.3 PowerPointへの画像コピー

対象テーマ・期間・行を選び、単一の日程をプレビュー後にPNG画像としてコピーする。当初予定・実績の比較は表示しない。

- 白背景と読みやすい文字色を使い、アプリの明暗テーマに依存させない。
- 左のタイトル一覧は出力せず、単一日程のバーの左端に重ねてタイトルを表示する。短いバーは文字を右にはみ出して表示できる。単日も1日幅のバーとする。日程未定／期間外の行は同じ領域へバーなしで名前を表示する。操作ボタン・サイドバー・選択枠は含めない。
- スクロール外も含めて指定行を描画する。長い日本語行名は折り返す。
- 月と日番号を上下2段に分離し、日番号は全日を表示する。全日表示で重なる幅の場合は、飛び飛びの日番号ではなく週頭の月曜日だけを表示する。（2026-11-07 ユーザー更新）
- サイズ・解像度を調整可能。縦横比を歪めず、PowerPointの16:9スライドに配置して判読性を確認する。
- 指定期間外のバーは表示範囲でクリップする。日程未定はバーなしとする。
- 空の選択や過大な画像は理由を示して調整を促す。行やラベルを黙って欠落させない。
- Electronのクリップボード操作で画像を出力し、成功／失敗を表示する。PowerPoint内で編集可能な図形への変換は対象外。

## 5. 編集・保存・画像

### 5.1 入力と自動保存

タイトルだけで作成でき、作成欄へ自動フォーカスする。日本語変換確定中のEnterでは登録しない。本文内のEnterは改行する。

アプリ内の新規登録ウィンドウは、開いた直後から最初の入力欄へ入力できる。ページ・テーマ・関連ページ・計画行はタイトル欄、資料追加は呼び出し元に関係なくパス／URL欄、ページからの計画追加は新しい計画行の名前欄へフォーカスする。開いた後に利用者が検索欄などへ移動した場合は、再描画でフォーカスを戻さない。閉じて開き直したときは再び最初の入力欄へ合わせる。（2026-11-06 ユーザー指示）

新規作成が成功したら作成ウィンドウを閉じ、元の一覧・ページを表示する。作成したページの詳細や新しいテーマへ自動遷移せず、空の作成ウィンドウも維持しない。ホーム・テーマ内・関連ページ・テーマ作成に共通して適用する。作成失敗時はウィンドウと入力を保持する。（2026-11-04 ユーザー指示による更新）

編集は自動保存し、通常の画面移動で保存確認を繰り返さない。保存中・保存済み・下書き保持などの通常状態を常設表示せず、失敗した場合だけ警告と再試行を表示する。上部・資料詳細・新規登録・本文画像などアプリ全体に適用する。失敗時の入力保護・復旧案内・正常終了時の保存待ちは維持する。計画の日程ドラッグ中もEsc取消の文言を表示しないが、Escによる取消操作は維持する。（2026-11-07 ユーザー指示）

本文は見出し・箇条書き・番号付きリスト・チェックリスト・リンク・画像を整形した状態で編集する。行頭で `# `〜`###### ` を入力すると見出し1〜6、`- ` は箇条書き、`1. ` は番号付きリスト、`[ ] `／`[x] ` はチェックリストになる。記号に続く半角スペースで変換する。これはMarkdown風の入力ショートカットであり、既存の本文をMarkdownとして再解釈したり、ソース表示へ切り替えたりはしない。（2026-11-05 ユーザー指示）

書式ボタンは常設せず、本文の右クリックメニューへまとめる。標準／見出し、太字・斜体、各リスト、リンク編集、画像追加をここから操作する。選択した文字範囲を保持し、チェック項目内では「ページにする」、画像では拡大・本文からの削除も利用できる。切り取り・コピー・貼り付けとUndo／Redoも同じメニューに含め、Shift+F10でも開ける。アーカイブ等の読み取り専用時は書式変更・切り取り・貼り付け・削除を表示せず、コピーや画像拡大を利用できる。（2026-11-06 ユーザー指示）

チェック項目内では「ページにする」から関連ページ追加画面を開き、チェック項目の文字をタイトルの初期入力にする。作成は未着手でテーマと関連を継承し、元ページに残る。元のチェック項目とチェック状態は保持し、失敗時に本文を削除しない。

本文の「メモを書き始める…」は本文全体が空の標準段落1つのときだけ表示する。空のリスト項目や入力済み本文の空行には表示せず、スクロール時も残さない。（2026-11-06 不具合修正）

未保存の入力は項目ごとの編集バッファで保持する。画面移動後も保存を継続し、失敗時は入力を残して再試行可能にする。正常終了では保存完了を待ち、失敗時に知らせる。編集中の内容をローカル下書きへ退避し、異常終了後に復旧できるようにする。保存失敗中の古い応答で新しい入力を上書きしない。

資料詳細の通常操作は「閉じる」とし、自動保存と重複する保存ボタンは置かない。保存失敗時のみ「再試行」を表示し、成功しても詳細を閉じない。詳細を閉じる・関連ページへ移動する際はその資料だけを保存対象とし、失敗時も入力と下書きを保持して移動できる。別資料の保存エラーで無関係な資料操作を止めない。終了・バックアップ時は全資料を対象に入力保護を確認する。保存失敗と資料目録の表示設定エラーは上部にも警告アイコンで示す。

空の資料追加画面は終了を妨げない。参照先を入力したまま、または登録失敗の参照先が残ったまま終了する場合は、未登録であることを示して画面へ戻る／破棄して終了を選べる。ほかの保存が失敗している場合は先にその入力保護を確認し、未登録入力の破棄だけで保存失敗を迂回しない。処理の実行中は保存エラーと区別して完了待ちを案内する。（2026-11-05 保存周りの改善）

アーカイブは状態と独立した可逆操作。テーマをアーカイブした場合、配下は通常一覧から除外するが、子の状態・個別アーカイブ値は書き換えない。復元時に元の状態を保つ。初期版のテーマ・ページの除去はアーカイブを基本とし、関連データの連鎖的な物理削除を行わない。

### 5.2 本文画像

クリップボード貼り付けとファイル選択で追加し、本文表示・拡大・本文からの削除を行える。画像はアプリ管理の添付領域へ保存する。参照元ファイルを移動しても表示でき、参照元には変更を加えない。

外部資料の登録と本文画像の取り込みは別操作。画像保存成功後に本文参照を確定し、失敗時は再試行できる。本文から消した直後に、下書きや復旧で必要な画像を物理削除しない。

取り込みはPNG/JPEG、1件20MiB・2400万画素以内とし、デコード検証後に管理用PNGとして保存する。ファイル名はアプリが発行するIDで、本文に元ファイルのパスを保持しない。表示はそのIDの管理画像だけを返す専用スキームを用いる。外部URL／SVG／アニメーション画像は取り込まない。画像一覧やカード型サムネイル表示、画像編集は初期版に含めない。

画像をクリックして拡大し、画像の右クリックメニューから本文の参照を削除できる。画像の保存失敗中は入力を保持してページから再試行し、明示的に未保存画像の入力だけを破棄することもできる。失敗画像を安全に保存できていない場合は、アプリ終了・バックアップ・対象ページのアーカイブを成功扱いしない。保存済みの本文・管理画像と外部原本は、失敗画像の入力破棄では変更しない。

## 6. データ・アーキテクチャ

### 6.1 責務

| 層 | 責務 |
| --- | --- |
| Electron main | DB、ファイル参照、外部起動、添付保存、画像コピー、バックアップ・復元 |
| preload | 必要な操作に限定した型付きAPI |
| React renderer | 表示、編集バッファ、検索操作、画面状態、報告画像の描画 |

rendererからNode.js・DBへ直接アクセスさせず、プロセス境界で入力値も検証する。任意コマンドを外部起動に渡さない。URLスキームとファイル参照を区別して検証する。

### 6.2 永続化する情報

| データ | 主な内容 |
| --- | --- |
| Themes | 名称、説明、並び順、アーカイブ |
| Items | タイトル、状態、任意のThemeId、サマリ、本文、期限、確認日、アーカイブ、作成／更新日時 |
| ItemLinks | 関連する項目ID、派生元か通常の関連か。派生元からも逆参照可能 |
| Documents | 表示名、参照先、推定種類、説明、作成／更新日時 |
| ThemeDocuments / ItemDocuments | 資料への関連、用途メモ、並び順 |
| PlanRows | 所属テーマ、名称、開始・終了日、並び順。旧当初予定・実績の日付は非表示で保持 |
| PlanItemLinks | 計画行とページの多対多関連 |
| Attachments | 添付ID、アプリ管理の相対パス、画像形式・サイズ等 |
| Settings / Drafts | 表示条件・設定、未保存内容の復旧情報 |

内部IDを使い、同名の別項目は作成可能とする。本文はチェックリスト・画像参照が復元できる構造で保存する。SQLiteの変更はMigrationで管理する。DB・添付・下書きは新アプリ専用のローカル領域に保存し、旧アプリの保存先を再利用しない。

スキーマの具体的な列名や採用ライブラリは実装設計で確定する。派生関係と一般の関連リンクを、必須の階層構造へ置き換えない。

### 6.3 バックアップと復元

実データ運用前に、手動バックアップ、自動バックアップ、世代一覧、復元を実装する。DB・本文画像・復旧下書きを一組として、整合性のある世代を作る。資料原本は対象外で、参照先のみを保存する。

自動実行は30分間隔と正常終了時、完成済み30世代保持を初期設定とする。これは実装上の既定値であり、ユーザーの追加入力を要求しない。バックアップ先は設定でき、ネットワーク先の障害でも通常のローカル操作は継続する。

コピー途中の世代は完成済みとして表示しない。新世代の確定後に古い世代を整理する。失敗を通知・記録し、再試行可能にする。終了を無期限に妨げない。

復元前に世代と添付を検証し、現在データを退避する。通常の保存処理を止めてから置換し、再起動する。失敗時は元データへ戻し、空DBを作って続行しない。

## 7. UIの実装基準

操作試作で確認済みなのは情報構造と主要な流れ。試作の縦の長さ、列幅、入力欄の常設数は完成版の指定ではない。

- 余白・文字の強弱・整列を中心に構成し、カード・枠線・装飾を増やしすぎない。
- 市販アプリ並みのUI完成度を目標にする。Notionのようなミニマルな構成を基調に、意味のそろったアイコンと短いラベルで操作を分かりやすくする。余白・文字サイズ・コントラスト・フォーカス・保存状態・空の状態を一貫させ、実画面で調整する。（2026-11-03 ユーザー追加指示）
- 頻繁な操作は一覧・ページ内で完結させ、低頻度の設定はメニューへまとめる。
- 長い日本語タイトル・サマリ・パスを扱い、必要な全文へ到達できるようにする。
- 1366×768と1920×1080、Windows表示倍率125%・150%で、主要操作が切れずに使えるよう確認する。
- 一覧ヘッダー・ページ移動・頻用資料への到達距離を調整し、画面全体の縦伸びで頻用操作が遠くならないようにする。
- キーボードフォーカス、Tab移動、日本語IME、Enter／Esc、通常のテキストUndoを維持する。
- OSに従う明暗テーマを基本に、詳細配色・エディター・UIライブラリは実装時に選定する。

## 8. 初期版の対象外

- ページとタスクの別モデル、分類・タグ・優先度・表示コード。
- 再利用する資料セット、本文テンプレート管理、必須の親子階層。
- 本文の表編集、サムネイル一覧、画像編集。
- 原本本文検索、OCR、AI要約。
- カレンダー、OS通知、共同編集、クラウド同期、旧アプリからのデータ移行。
- ガントの依存関係・クリティカルパス・自動日程調整・複数基準計画の履歴。
- PowerPointの編集可能な図形やPPTXファイルの直接出力。
