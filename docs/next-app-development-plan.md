# Redia — 初期版の開発手順

版: 1.0 / 2026-11-03

対象仕様: [初期版確定仕様](next-app-spec.md)。本書は開発の順序と完了条件を定める。本パッケージを新規プロジェクトとして開いたら、START_DEVELOPMENT.md の指示に従って Phase 0 から実装を開始する。

## 1. 進め方

- この文書を含むプロジェクトのルートを新アプリの開発先とする（配布時のフォルダ名は `Migration`）。ルートへ `package.json` 等を作成し、`src/` 等を配置する。`desktop-next/` や二重の `Migration/` は作らない。フォルダは改名・移動可能。旧WPF版や親フォルダを参照・変更せず、このフォルダ内だけで開発する。
- 操作試作をそのまま製品コードとして継ぎ足さず、共通のデータモデルとサービスを先に作る。
- 各段階で起動可能な状態と確認用サンプルを用意する。テストデータは製品用データから分離する。
- 各段階の完了条件を満たしてから次へ進む。実データ運用は最終段階のバックアップ・復元確認後とする。
- 質問で決めた機能範囲を保ち、分類・タグ・優先度や独立した「いつか」画面を再導入しない。

## 2. 段階別の作業

### Phase 0 — 実装設計と環境

作業:

- リポジトリとローカルの作業指示を確認し、既存変更と新アプリを分離する。
- Electron・React・TypeScriptの構成とビルド／配布方法を決める。
- 現行の公式資料で互換性を確認し、UI・エディター・SQLite・画像生成に必要なライブラリを選定する。依存は最小限にし、バージョンとロックファイルを固定する。
- 型付きのAPI境界、DBのMigration、アプリ専用保存先、ログ、下書き・添付の配置を決める。
- 機能仕様を変えずに、サマリ長・画像形式とサイズ上限・検索性能の基準を決めて記録する。

成果物: 起動する空のシェル、構成説明、開発・ビルドコマンド、技術選定記録。

完了条件: Windowsで起動・終了・再起動でき、rendererのDB／Node.js直接アクセスを許可しない。旧アプリの保存領域を使用していない。

### Phase 1 — 永続化と最小の作業導線

作業:

- テーマ、共通のページ、6状態、サマリ、期限・確認日、項目間の関連を実装する。
- 新規ページは未着手で作成し、関連ページ追加からの作成ではテーマと関連を継承する。2026-11-05のユーザー更新により、気づき専用ボタンは非表示とする。
- 最小のホーム、テーマ一覧、詳細ページと、自動保存・失敗時だけの警告表示・入力保護を実装する。通常の保存中／保存済み表示は2026-11-07のユーザー更新により非表示とする。
- 手動バックアップの基盤を作り、DB変更を安全に検証できるようにする。

成果物: タイトルだけで作成し、元ページから関連ページを作り双方向にたどれるアプリ。

完了条件: A01〜A03・A06のデータ操作と再起動後の保持を確認。保存失敗・古い応答・IME入力を確認し、入力が消えない。

### Phase 2 — ホームと日々の整理

作業:

- 表形式の主一覧と独立した「いつか」常設欄を実装する。
- 状態・サマリの一覧内編集、検索、状態／テーマのフィルター、並べ替え、任意列を実装する。
- 完了・中止の主一覧除外、テーマでの再表示・再開、アーカイブ／復元を実装する。
- 期限・確認日の案内、条件の永続化、戻る操作と位置復元を仕上げる。

成果物: 今取り組むことと将来のことを、同じホームから管理できる状態。

完了条件: A03〜A06・A11・A15を確認。「いつか」がフィルターで消えないこと、完了・中止が主一覧へ混ざらないこと、状態変更でサマリが保持されることを確認。

### Phase 3 — 資料目録と文脈別の資料

作業:

- 資料目録、ファイル／フォルダー選択、パス／URL登録、複数ドロップ、重複再利用を実装する。
- ページ・テーマへの関連付け、用途メモ、一覧全体の並べ替えを実装する。初版ではグループ化しない。
- 資料詳細からの原本起動、行メニューからの共通情報編集・参照先修正・登録解除を実装する。
- 資料名・参照先・用途メモによる検索、種類・テーマの絞り込み、関連ページへの移動を実装する。

成果物: 実験ページのマニュアル・手順書・メモ・計算シートと、全資料の目録を行き来できる状態。

完了条件: A07〜A10・A22の資料操作を確認。複数登録の部分失敗、参照切れ、共有先未接続、同名別資料、同一資料の複数関連を検証する。原本への変更がないことを確認。

### Phase 4 — 本文・画像・横断検索

作業:

- 本文の文章・見出し・箇条書き・チェックリスト・リンクを仕上げる。
- 画像貼り付け／選択・保存・表示・拡大、添付参照と復旧下書きの整合性を実装する。
- チェック項目の独立ページへの切り出しを実装する。
- Ctrl+Kの横断検索、最近開いた対象、非同期結果の破棄、アーカイブを含む検索を実装する。

成果物: 記録・画像・資料を持つページをスムーズに入力・再発見できる状態。

完了条件: A12〜A14を確認。原本本文や画像内文字が検索対象と誤認されない表示にする。添付元の移動・画像保存失敗・異常終了・復旧後の編集を確認。

### Phase 5 — 独立した計画とガント

作業:

- 計画行の作成・編集・削除・並べ替え、日程未定も含む共通一覧、複数ページとの関連を実装する。
- 2026-11-06の仕様更新により、開始／終了の単一日程・単一バーへ変更する。当初予定・実績の旧データは保持し、比較・当初保存・実績入力を非表示にする。
- 週・月・クオーターの表示密度、折りたためるタイトル列、バー上のタイトル・月／日の軸・土日の区別を実装する。カレンダー内部の縦方向の表示領域制限は設けない。
- カレンダーのクリック／期間ドラッグ・バー移動／伸縮・取消・Undoと、最下段の空欄からの行追加・各行の直下への挿入・即入力を実装する。
- タイトルやバーから右側の詳細パネルを開く。1366×768と狭い画面でも操作対象と日付を確認できる配置に調整する。

成果物: ページに日程入力を強制せず、カレンダー上で計画を直接管理できる状態。

完了条件: A16〜A19を確認。クリック／逆方向を含む期間選択、未定・片側・単日、行の追加／挿入、タイトル列の開閉、期間の順序、非表示の旧データ保持、保存障害と復旧を検証する。

利用確認: 一時テストデータで日程設定・移動・伸縮・行の連続追加を実行する。関連ページの状態との自動同期は導入しない。

### Phase 6 — 報告画像とバックアップ・復元

作業:

- 対象テーマ・期間・行、サイズ・解像度を選ぶ単一日程のプレビューを実装する。当初予定・実績の比較は再導入しない。
- 白背景のPNG生成とElectronのクリップボードへの画像出力を実装する。
- DB・添付・下書きを含む整合したバックアップ、周期／終了時実行、世代整理、復元前の退避とロールバックを仕上げる。
- アプリのインストール／更新手順、保存先とバックアップ範囲を文書化する。

成果物: PowerPointで報告でき、復旧可能な初期版候補。

完了条件: A20〜A22を確認。PowerPointへの実貼り付けとテストデータの復元を行う。復元後に本文画像が表示され、外部資料は参照先として残ることを確認する。

### Phase 7 — 実画面の調整と初期版確定

2026-11-07時点: 総合回帰、12条件の画面検証、拡大時の資料追加修正、フォルダー版／NSIS生成、[操作ガイド](USER_GUIDE.md) と [継続改修手順](MAINTENANCE.md) を整備した初期版候補。Windows操作ツールがテスト窓を取得できず、A01・A13・A20・A22・A23の手動残件は維持する。以下の完了条件は未達成。利用中の修正を続けながら実機確認を進める。

作業:

- 余白・列幅・スクロール範囲・詳細の開き方を実画面で調整する。操作試作の縦の長さを踏襲しない。
- 1366×768／1920×1080、125%／150%でホーム・資料・本文・ガントを確認する。
- キーボード・IME・フォーカス・コピー・外部起動と、異常時の案内を実機で確認する。
- A01〜A23の確認結果と未解決事項を記録する。

成果物: ビルド済み初期版、短い操作説明、受入確認記録。

完了条件: 全受入条件の必要な自動／手動確認が通り、保存・復元・原本保護に未解決の問題がない。

## 3. 検証方法

| 検証 | 対象 |
| --- | --- |
| ロジック・DBテスト | 状態別の一覧条件、テーマ所属、派生リンク、関連資料、日付、旧計画データの保持、Migration |
| コンポーネント／操作テスト | 一覧編集、フィルター、戻る操作、気づき作成、自動保存の競合・失敗 |
| ファイル／復旧テスト | 添付保存、資料原本不変、参照切れ、バックアップ部分失敗、復元とロールバック |
| Windows実機確認 | IME、表示倍率、既定アプリ起動、実クリップボード、PowerPoint貼り付け、異常終了後の復旧 |

自動テストは一時DB・複製ファイル・模擬障害を使い、実資料や旧アプリのDBを変更しない。試作の簡易DOM検証は実アプリの受入確認の代わりにしない。

検索性能はPhase 0で想定データ件数と検証PCを決め、対象件数・測定条件とともに基準を記録する。推測のベンチマーク結果を記載しない。

## 4. 実装開始時に決める細部

次は機能の追加相談ではなく、開発中に根拠を残して決める実装事項。

- Electron／Node.js／Reactと各ライブラリの互換性・バージョン・ライセンス。
- サマリの上限、画像形式・ファイルサイズ上限、画像保存形式、破損時の扱い。
- DBスキーマ・保存先・Migration・APIの型と検証。
- 検索件数・性能基準、描画範囲・画像生成の上限。
- ガントのドラッグ単位・表示粒度ごとの編集可否・Undoの範囲。
- 画面のスクロール構成、列の初期幅、明暗テーマ、配布方法。

情報構造や必須入力を増やす変更、状態の追加、初期版の対象外機能の導入は、実装都合だけでは行わず仕様変更として扱う。
